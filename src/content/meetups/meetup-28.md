## About Event

BTU Tech Hub: 28th Meetup

**Connect • Learn • Build**

Meetup #28 was a different kind of session: instead of building a project, each participant took a well-known product, picked one feature, and reverse engineered how it works, using only the **REA (Reverse Engineer Anything)** GitHub repo and no implementation.

### The Challenge: Reverse Engineer a Feature, Don't Build It
The goal was to understand real products deeply enough to explain their architecture, data flow and key design decisions:
- **One Participant, One Feature:** Everyone chose a single feature of a product they use and care about.
- **REA-Driven Analysis:** The REA approach was used to break each feature down into components, flows and integrations, without writing the actual project.
- **Explain It Like an Architect:** The focus was on how the feature is structured and why, not on shipping code.

### Features We Reverse Engineered
- **FlowCV (Resume Maker) with Google Drive Integration:** How the FlowCV resume builder works and along with Google Drive integration is designed.
- **Microsoft Word:** Breaking down how a full-featured Microsoft word works under the hood.
- **Granola-Style Meeting Detection & Note Taker:** How a tool detects meetings and turns them into structured notes.
- **Notion:** One feature reverse engineered from Notion.
- **Mac Wall:** One feature reverse engineered from Mac Wall.
- **Notch Box:** One feature reverse engineered from Notch Box.
- **Obsidian Graph View with AI Agents:** How the graph view models notes and links, and how AI agents can reason over and extend it.
- **Figma:** One feature reverse engineered from Figma.
- **Evernote:** One feature reverse engineered from Evernote.

## Presentations by Participants

The session closed with individual presentations:
- **Individual Presentations:** Each participant presented their reverse-engineered feature, walking through its architecture and the key insights they uncovered. The presentations turned out very well.
- **Different Products, Shared Method:** Despite very different features, everyone applied the same REA workflow, which made the comparisons interesting.
- **Collaborative Feedback:** The room exchanged questions and ideas on how each feature could be built and extended.
